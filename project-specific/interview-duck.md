# 示例：通用规则在一个真实项目里的落地形态

> 这份**不是通用规则**，是一个真实项目（Electron 桌面应用）的具体形态，用来说明"参数化"长什么样。
> 换项目时：读它、照结构、换掉具体的东西，**不要把内容带过去**。

## 30 条规则的具体化示例

| 通用条款 | 在这个项目里长什么样 |
|---|---|
| V1 断言要能变红 | 语音首声耗时断言：正常 0.7s、故障 >2.5s、噪声 0.25s → 阈值定 2.5s |
| V3 连跑两次仍绿 | 验收直接读写真实库，第一版把上限写死 1，第二次必红 → 改成读基线 + 动态断言 + 结尾还原 |
| V6 SKIP≠PASS | 在线语音受微软配额限制，429 时打 SKIP 而不是 FAIL，并单独计数 |
| V7 窗口降级 | 截图走 `fromSurface:false → jpeg → 默认`，截图前先 `setWindowBounds({windowState:'normal'})` |
| DT4 删数据前备份 | 任何 `rm data/*.db` 之前先 `cp` 到 `data/backups/` |
| U4 冒烟同步断言 | 改设置页控件名，必须同步改 `tests/ui-smoke-main.js` 里的选择器 |
| EN4 高频路径禁整表读 | `getState()` 会整表读题目（151 题 2042ms），逐句合成路径改走 `getSettings()` + 主进程缓存 |
| CO5 门禁留 merge 通道 | `commit-msg` hook 检测到 `MERGE_HEAD` 就放行，否则 `merge:` 前缀会被拒、合并卡死 |
| EN1 环境并存 | **本项目没做到**（单实例锁导致验收必须用户先关应用，累计阻塞 5 次），这是反面案例 |

## 项目独有的陷阱（绝对不要带走）

- **`ELECTRON_RUN_AS_NODE=1`**：Electron 类宿主会注入此变量，导致 `npx electron` 降级成纯 Node。修法：命令前加 `env -u ELECTRON_RUN_AS_NODE`。
- **单实例锁是目录**：`node-sqlite3-wasm` 用 `xxx.db.lock` 目录模拟文件锁，进程被强杀不释放。启动时要先确认单实例再清残留锁。
- **语音合成必须进纯 Node 子进程**：Electron 运行时禁止外部缓冲区，`sherpa-onnx-node` 在主进程调用必抛 `External buffers are not allowed`。
- **桌面快捷方式脚本必须 UTF-8 BOM**：PowerShell 5.1 否则按 GBK 解析中文报错。
- **数据删除前无备份导致误删**：一次终验为"全新灌库"直接删库，丢了用户手动录入的数据。

## 从这个项目得到的、与项目无关的三条结论

1. **验证类错误占 43%**，且全部发生在"我以为验证过"之后 → 通用层把验收独立成组（V 组 8 条）。
2. **"已拍板"必须有独立文件承载**，否则跨会话必丢（语音方案定稿 4 天后还在静默用旧方案）→ `DECISIONS.md`。
3. **错因本必须收流程摩擦**，只收代码错误会漏掉最贵的阻塞（单实例锁 5 次一条未记）。
