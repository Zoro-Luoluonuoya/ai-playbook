# 使用手册：在新环境用 Codex 跑这套框架

> 实测环境：Windows 11 + Codex 桌面版 + PowerShell + Git Bash（2026-11-07 实跑，非推演）
> 适用：换新电脑、换新项目、换新工具时怎么把规范装进去并确认它真的生效。

---

## 三十秒版

```powershell
# 1) 拿到规范（只做一次）
git clone https://github.com/Zoro-Luoluonuoya/ai-playbook "$env:USERPROFILE\ai-playbook"

# 2) 装进项目（每个新项目一次）
& "E:\git\Git\bin\bash.exe" -c "cd '/c/Users/你/ai-playbook' && sh install.sh '/c/你的/项目路径'"

# 3) 验它读没读（10 秒，别省）
#    问 Codex：「CLAUDE.md 的『常用命令』逐行贴原文给我」
#    它贴出带尖括号的占位符 = 生效；写出 npm start 之类 = 没生效
```

---

## 第一段：新电脑，一次性准备（约 5 分钟）

### 1.1 确认环境

发这一段：

```
先确认环境，跑这三条，输出原样贴我：
where.exe git
where.exe bash
git --version
```

**怎么看结果：**

| 输出特征 | 结论 | 怎么办 |
|---|---|---|
| 有 `E:\git\Git\bin\bash.exe` 或 `C:\Program Files\Git\bin\bash.exe` | 有 Git Bash，可用 | 记下路径，后面所有命令都用它 |
| 只有 `C:\Windows\System32\bash.exe` | **这是 WSL，不能用** | 让 Codex 跑 `Test-Path "C:\Program Files\Git\bin\bash.exe"` 找 Git 自带的 |
| 两条都没有 | 没有 bash | 走文末「没有 bash 怎么办」 |

> **为什么不能用 System32 的 bash**：那是 WSL 入口，进去是 Linux 环境，`C:\Users\...` 会变成 `/mnt/c/Users/...`，中文目录大概率挂掉。

### 1.2 Clone 到固定位置

```powershell
git clone https://github.com/Zoro-Luoluonuoya/ai-playbook "$env:USERPROFILE\ai-playbook"
```

**不要放 Temp。** Temp 会被系统清理，而且下次容易用到旧副本。

已存在就先更新，别直接用：

```powershell
git -C "$env:USERPROFILE\ai-playbook" pull
git -C "$env:USERPROFILE\ai-playbook" log --oneline -1
```

> **真实踩坑**：Codex 发现 Temp 里已有旧的 clone，就按"已存在"复用了，差点测的是旧版本。看到 `already exists` 时，先 `pull` 再继续。

### 1.3 记下版本号

把上一步 `log --oneline -1` 的输出记下来。以后行为异常时，第一件事是对版本。

## 第二段：每个新项目，装一次（约 1 分钟）

### 2.1 装进去

```powershell
& "<Git Bash 路径>" -c "cd '/c/Users/<你>/ai-playbook' && sh install.sh '/c/<项目路径，用正斜杠>'"
```

Windows 路径转 Git Bash 写法：`C:\Users\me\proj` → `/c/Users/me/proj`。

期望输出：

```
完成：写入 11 个，跳过 0 个（已存在）。
```

11 个文件 = 8 个骨架（CLAUDE/AGENTS/DECISIONS/spec/MISTAKE-LOG/DoD/每日三问/new-project.sh）
+ 3 个基线（.gitattributes / scripts/verify.sh / .claude/rules/通用规则-30条.md）。

> 中文目录名实测没问题（`规则试验` 跑通了）。

### 2.2 验它真的读了（**这一步不能省**）

发这一句：

```
装完了。现在回答：把 CLAUDE.md 里「常用命令」那一节的原文逐行贴给我，
不要总结、不要补全、不要推测。

如果你没读到，就直接说"没读到"。
```

**判据只有一条：看它贴出来的是不是尖括号占位符。**

| 它贴的内容 | 结论 | 下一步 |
|---|---|---|
| `<启动命令>`、`<单测命令>` 这种带尖括号的 | ✅ **真读了** | 继续 |
| `npm start`、`npm test` 这种看着合理的 | ❌ **它在编** | 说明规范没生效，检查装没装对 |
| 「CLAUDE.md 里没有这一节」 | ❌ 没去读 | 把 AGENTS.md 里"开工前读 CLAUDE.md"改成硬动作 |

**为什么用这一句而不是跑脚本**：跑脚本只证明文件在；这一句证明它**打开看了**。今天就是靠它确认整条链通的——它老老实实贴出了 7 行占位符。

### 2.3 填内容，再跑自检

按顺序做：

1. **`CLAUDE.md`**：填「常用命令」和「架构三句话」。写不出来就照实写「未定」，**不要编**。
2. **`DECISIONS.md`**：写第一条决策（比如交付形态、技术栈）。还没定就写「待定」。
3. **`docs/spec.md`**：填「明确不做」至少 5 条。

然后跑：

```powershell
& "<Git Bash 路径>" -c "cd '/c/<项目路径>' && sh scripts/verify.sh"
```

**装完第一次跑，一定红 2 项**：

```
FAIL  spec「明确不做」只有 0 条真实条目（要求 ≥5）
FAIL  DECISIONS 还没有真实决策
```

**这是设计如此，不是装坏了。** 脚本自己会打印「这是正常的——说明模板还没被填成你自己的项目」。

填完内容再跑，应该全绿。想确认检查本身没坏：

```powershell
& "<Git Bash 路径>" -c "cd '/c/<项目路径>' && sh scripts/verify.sh --selftest"
# 应输出：SELFTEST OK: 占位计 0、真实计 5、代码块示例计 0
```

> **它会误判这一步**：看到 red 就想"帮你修一下"。纠正它：「这是预期行为，不是 bug，别修。」

### 2.4 初始化 git

```powershell
git init
git add -A
git commit -m "chore: 装入开发规范"
```

不做这步，回滚和 worktree 并行都用不了。

## 第三段：日常干活

装好之后**不用再教它规矩**。直接给任务：

```
给这个项目加 <功能>。按规范来。
```

它应该做到：

- 读 `CLAUDE.md` 和 `DECISIONS.md`（AGENTS.md 要求）
- 先给「打算怎么做 + 要你拍板什么」
- 干完给四件套：改了哪些文件 / 命令与输出原文 / 界面证据 / 关键行为结果
- 点名「哪层没跑」

**你只需要在两件事上补一句**：

| 它漏了什么 | 你说 |
|---|---|
| 跳过开工计划，直接干完 | 「停。按 AGENTS.md 的『开工前』，补上『打算怎么做』和『要拍板什么』。」 |
| 没写「哪层没跑」 | 「补上：哪一层没跑、为什么。」 |

实测它的遵守率大约 80%——小任务（比如写一行脚本）会跳过计划，这是它认为"没有决策点"。补一句就能拉回来。

## 实测踩过的六个坑

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | Codex 桌面版是 **PowerShell**，不是 bash | `ls -la` 报「找不到与参数名称 la 匹配的参数」 | 给它命令用 PowerShell 语法：`Get-ChildItem`、`Copy-Item`、`$env:TEMP` |
| 2 | `where.exe bash` 第一条是 **WSL** | `C:\Windows\System32\bash.exe` | 必须显式用 `E:\git\Git\bin\bash.exe` |
| 3 | Temp 里的旧 clone 被直接复用 | `already exists and is not an empty directory` | 先 `git pull`，再确认 `log` 是预期版本 |
| 4 | 装完第一次跑 verify 一定红 | 2 项 FAIL | 设计如此。填完内容就绿 |
| 5 | 中文项目路径 | —— | **没问题**，实测通过 |
| 6 | 模板脚本曾是 CRLF | 换 Linux 会报 `bad interpreter: /bin/sh^M` | v1.0.3 已修，`.gitattributes` 加 `*.sh.template` 规则 + install 时剥离 |

## 排错速查

| 报错 | 原因 | 处理 |
|---|---|---|
| `install.sh: not found` | clone 没成功 / 不在正确目录 | 先 `Get-ChildItem` 确认 |
| 路径 `No such file` 但看着对 | 用了 WSL 的 bash，路径被映射了 | 换成 `E:\git\Git\bin\bash.exe` |
| `permission denied` | 沙箱限制 | 让它说明限制范围，或改到用户目录下 |
| 装了但 Codex 说没看到规则 | 目录不是 Codex 的当前工作目录 | 确认 `pwd` 指向项目根 |
| 它答的规则对但来源都是 AGENTS.md | 只读了入口，没读第二个文件 | 用 2.2 的占位符测试验证 |

## 这套东西能保证什么 / 不能保证什么

**能保证：**

- 规则会**被读到**（Codex 对 `AGENTS.md` 是硬约定，启动必读，并会按引导读 `CLAUDE.md` 与规则文件）
- 交付格式统一（四件套 + 点名未跑层）
- 决策有账本（`DECISIONS.md`，带作废条件）
- 踩坑会升级成规则（`MISTAKE-LOG` → 门禁）
- 骨架不完整时**会红**（`verify.sh` 有区分力，`--selftest` 可自证）

**不能保证：**

- **100% 遵守**。实测约 80%，压力下（任务急、上下文长）会更低。门禁只兜住了「改 renderer 没跑冒烟」这一条
- **替你决定做什么**。它管"怎么做才算做对"，不管"该不该做"
- **跨工具零改动**。Claude Code 认 `CLAUDE.md`（已有），Cursor 要自己拆 mdc
- **记住你的偏好**。规则是"必须做什么"，偏好是"做成什么样"，后者需要你自己填 `USER.md`（本仓库暂未提供模板）

## 没有 bash 怎么办

用 PowerShell 手工复制，效果等同 `install.sh`：

```powershell
$src = "$env:USERPROFILE\ai-playbook"
$dst = "C:\你的\项目路径"
New-Item -ItemType Directory -Force -Path "$dst\.claude\rules","$dst\docs","$dst\scripts" | Out-Null
Copy-Item "$src\templates\CLAUDE.md.template"      "$dst\CLAUDE.md"
Copy-Item "$src\templates\AGENTS.md.template"      "$dst\AGENTS.md"
Copy-Item "$src\templates\DECISIONS.md.example"    "$dst\DECISIONS.md"
Copy-Item "$src\templates\spec.md.template"        "$dst\docs\spec.md"
Copy-Item "$src\templates\MISTAKE-LOG.md.template" "$dst\docs\MISTAKE-LOG.md"
Copy-Item "$src\templates\DoD-验收清单.md"          "$dst\docs\DoD-验收清单.md"
Copy-Item "$src\templates\每日三问.md"              "$dst\docs\每日三问.md"
Copy-Item "$src\templates\new-project.sh"          "$dst\docs\new-project.sh"
Copy-Item "$src\templates\gitattributes.template"  "$dst\.gitattributes"
Copy-Item "$src\templates\verify.sh.template"      "$dst\scripts\verify.sh"
Copy-Item "$src\core\规则-30条.md"                  "$dst\.claude\rules\通用规则-30条.md"
(Get-ChildItem $dst -Recurse -File).Count   # 应为 11
```

复制完同样要做 2.2 的占位符测试——**复制成功不等于它读了**。
