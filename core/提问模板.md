# 提问模板（Spec 门禁的操作化版本）

> 门禁的实质不是"写一份 spec 文档"，而是**歧义清零**。这份模板是一段可以直接套用的回复结构。

## 什么时候必须用

- 需求里出现"改成""加一个""优化一下"这类没有验收标准的动词
- 要改公共接口、数据结构、界面口径
- 我上一轮理解和你说的可能不是一回事（你说了"不是""我没搞清楚"）

## 模板

```markdown
先不动代码。我按下面两点跟你对一遍。

**一、我打算默认这么处理（不同意就说）**
1. <结论性动作>
2. <结论性动作>
（每条都要能变成一个可检查的结果，不要写"优化""完善"）

**二、必须你拍板的（按影响度排序）**
1. <问题>：A <选项与后果> / B <选项与后果>
2. <问题>：...

**三、我不打算做的**
- <明确排除项>（防止范围蔓延）
```

## 有效提问 vs 无效提问

| 无效（消耗判断力） | 有效（真的需要你） |
|---|---|
| "历史数据要回填吗？" —— 数据本身没有不一致，这个问题不存在 | "库里已有 12 条旧格式记录，要一次性转换还是留着不动？" |
| "你希望界面好看一点吗？" —— 无验收标准 | "这一列显示总题量还是今日剩余？两种都合理，取决于你拿它做盘点还是做计划" |
| "要不要增加错误处理？" —— 答什么都对 | "接口失败时：A 提示重试且不落库 / B 落库后标记失败。选 A 会丢草稿，选 B 会产生脏数据" |

## 判据

一个待决项如果「两个选项我自己选且风险相同」，就不要问——直接选，并标注"已默认，不同意就说"。

**反例（真实发生）**：我曾提"历史数据要回填不回填"，用户回"什么回填不回填，我没太搞清楚"。查完发现库里根本没有不一致的数据——我在用伪选择题消耗他的判断力。

## 确认成本要低

门禁不是仪式。让用户只需要回一个字（`加` / `开工` / `关了`）就能过闸，才可能长期执行。
