## 怎么用这份清单

1. **红线（违反必返工）**：不是「注意一下」，是触发即停。命中红线时不允许以「这次改动小」「已经跑过一遍」为由跳过，也不允许在交付说明里用「应该没问题」代替执行记录。红线共 22 条。
2. **强约束（偏离需说明理由）**：默认执行；确有更合适的做法时可以不做，但必须在交付说明里写清「哪条、为什么不适用、替代动作是什么」。不写说明的偏离按红线处理。
3. **建议（可选）**：做与不做不影响验收。本清单 8 条强约束、0 条建议——凡是能写进来的都有事故来源，没有事故支撑的写法一律进「候选（待证）」，等补到证据再升级。

使用时按任务类型检索，不要从头读：改 UI 看第 ③ 组，改数据层看第 ② 组，写验收脚本看第 ① 组，接外部服务看第 ④ 组。

**编号前缀**：`V` 验证 / `DT` 数据 / `U` UI / `AI` 外部服务 / `CO` 协作 / `EN` 环境。
刻意避开 A/B/C/D 单字母——`00` 与 `01` 里用 A/B/C/D 指「有效机制 / 范式漏洞 / 错误图谱 / 内容生产线」四类结论，两套编号不能串线。
本文所有「来源」若写「结论骨架 Bx」，即指 `raw/结论骨架.md` 里对应编号，可顺着它再追到 M 编号或会话轮次。

## ① 验证与验收（8 条）

验证类错因 10 条（占原有 23 条的 43%、全量 28 条的 36%），且全部发生在「我以为已经验证过」之后。本组规则针对的是「验证系统自己会骗人」。

### V1 验收断言必须自证区分力

- **规则**：断言要先证明「坏的时候会红」，否则不算验收。
- **触发**：写性能、缓存命中、引擎复用、优化效果类断言。
- **来源**：M-012 / M-007
- **违规症状**：两次耗时都在 5.5 秒量级、只差 250ms，断言随 CPU 抖动随机红；或者把被测代码改坏，断言依旧绿。
- **自查**：写下正常值、故障值、噪声水平三个数；正常与故障的差距小于噪声量级就重写断言。
- **等级**：红线

### V2 性能断言只用唯一输入、只判可控耗时

- **规则**：耗时断言必须用每次唯一的输入，且只判自己可控的部分。
- **触发**：首声延迟、冷启动、缓存类断言。
- **来源**：M-007（两处）/ M-007 追加
- **违规症状**：固定句子跑第二遍命中缓存，实测 52ms，这条检查从此永远为真；或者同一份代码上轮 1.1 秒、这轮 8.4 秒，红的其实是第三方网络的当时延迟。
- **自查**：断言里是否带时间戳或先清缓存；耗时里是否混入外部网络——混入的部分只打印，不进失败条件。
- **等级**：红线

### V3 同一条验收必须连跑两次仍绿

- **规则**：验收脚本要在同一环境连跑两次都全绿才算过。
- **触发**：写任何读写真实库的验收脚本。
- **来源**：M-010
- **违规症状**：第一遍全绿，第二遍在「复习一张后队列清空」处失败，日志显示点了个 null；单看像功能坏了，实际是测试把状态带进了下一轮。
- **自查**：不改任何数据，连跑两次，逐条比对输出；第二次出现新红点就是脚本自身有跨运行状态。
- **等级**：红线

### V4 动用户数据的验收按「基线→期望→还原」三步

- **规则**：涉及用户数据的验收先读基线，按基线算期望，结束时还原。
- **触发**：每日上限、打卡计数、连续天数、复习队列类验收。
- **来源**：M-010
- **违规症状**：断言里写死 0/1、1/1 这类绝对数字，第二天跑必红；或者跑完验收，用户的 dailyGoal 被永久改成 1。
- **自查**：脚本里搜硬编码数字，换成 `baseDone + N` 和动态正则；确认末尾有还原语句。
- **等级**：红线

### V5 回归范围按改动影响面裁剪

- **规则**：回归只跑本次改动影响到的层，不跑「能跑的全部」。
- **触发**：每次交付前的全量回归。
- **来源**：M-015
- **违规症状**：一天十几次真实联网合成 → 429 限流 → 语音断言红 → 自己花一轮排查「是不是我改坏了」。用户直接问「语音问题我们不是已经说好了选定谁吗？为什么现在还一直在测试语音」。
- **自查**：列出本次改动的文件，映射到验收条目；映射不上的条目默认关闭，需要时手动 `--voice` 打开。
- **等级**：强约束

### V6 外部依赖断言必须有 SKIP 分支，SKIP≠PASS

- **规则**：依赖外部配额的断言必须能明确跳过，跳过不计入通过。
- **触发**：验收含在线语音、第三方 API、任何有配额的接口。
- **来源**：M-014
- **违规症状**：`engine=local`、首声 18 秒、裸测端点报 HTTP 429；四条语音全红，看着像产品坏了，实际是微软限流。
- **自查**：断言里每个网络调用都确认有「不可用→skip」分支，且 skipped 单独计数、不写成 PASS。
- **等级**：红线

### V7 依赖窗口可见性的步骤必须多级降级

- **规则**：截图、拖拽、焦点类步骤必须写降级路径，失败只降级不中断。
- **触发**：CDP 驱动的真机验收脚本。
- **来源**：M-009 / M-009 补充
- **违规症状**：前面 24 条全绿，最后一步 `Page.captureScreenshot` 卡 20 秒、45 秒后超时，整轮判 FAIL；同一脚本首轮还成功过。
- **自查**：搜 `captureScreenshot`，确认 `fromSurface:false` → jpeg → 默认三种都在，且截图前有 `bringToFront` 与窗口状态还原。
- **等级**：红线

### V8 交付说明只点名「与本次改动相关」的未跑层

- **规则**：只点名本次改动能影响到、且没跑的那几层。不相关的层不提——提了就是仪式。
- **触发**：任一次交付。
- **来源**：M-008 + 2026-11-07 仪式化修订。原规则要求「五层逐项写」，实测退化成「未跑：完整测试套件」这种零信息占位。
- **违规症状**：① 漏报——M-008：ui-smoke 一直 FAIL，隔整轮才发现；② 反方向的仪式化——每句话都挂「未跑：完整测试套件」，读者反而抓不到真信息。
- **自查**：先写「本次改动影响哪几层」，再只对这几层写跑没跑。判据：这段话换到别的任务里也成立 → 废话。
- **等级**：红线

## ② 数据与契约（5 条）

### DT1 查询函数不许有副作用

- **规则**：查询函数不许改状态，「取当前值」与「推进队列」必须分开。
- **触发**：写队列、游标、当前项读取。
- **来源**：M-013
- **违规症状**：`currentReviewCard()` 在渲染和评分两处都被调用，等于每渲染一次消费一次，同一道重做项永远卡在队首，队列走不完。
- **自查**：读函数体确认没有 `shift`/赋值/写库；推进动作单独命名并只在换题时调用。
- **等级**：红线

### DT2 状态类规则先验「重算是否同结果」

- **规则**：凡随操作变化的规则，先问「重算会不会得到同一结果」。
- **触发**：每日配额、复习队列、去重列表。
- **来源**：M-011
- **违规症状**：学掉一道后未学习少一道、配额又补一道，用户可以无限学下去，「每天 20 道」形同虚设；手点要第二张才露馅。
- **自查**：写一条「做一步之后结果应该变」的断言，而不是只写正向断言；重算路径与推进路径各断言一次。
- **等级**：强约束

### DT3 同一内容只留一个权威来源

- **规则**：同一份内容只允许一个权威来源，派生副本必须标「只读」。
- **触发**：seed 灌库、批量导入、回填工具。
- **来源**：结论骨架 D2（三处漂移：三大日志题 `selfAnswer`、十大排序题标题、AI大模型 6 题 `category`）
- **违规症状**：改了 seed 没回写库，或改了库没回写 seed；同一个标题在库里和种子里各是一个版本，没人知道哪个对。
- **自查**：列出该类内容的写入方，出现两个写入方就把非权威那侧标注「只读/派生」并写进注释。
- **等级**：强约束

### DT4 删除 data/ 下文件前必须备份

- **规则**：删除或覆盖 data/ 下文件前必须备份，生成数据不构成豁免。
- **触发**：验证「全新灌库」、重建库、清空缓存。
- **来源**：M-004
- **违规症状**：`rm -f data/interview-duck.db` 之后，用户验收期间手动加的题和复习记录一起没了；种子能再生，用户手数据不能。
- **自查**：命令里出现 `rm` 或覆盖重定向且路径含 `data/`，先 `cp` 到 `data/backups/`；验证灌库改用临时目录。
- **等级**：红线

### DT5 调没读过的接口先看实现

- **规则**：调用没读过的接口前先看实现，不按参数名猜语义。
- **触发**：调用 `toggleX(id, flag)` 这类形状的接口。
- **来源**：M-017
- **违规症状**：造了一道错题，执行 `toggleMistake(id, true)`，错题本里找不到它；第一反应是选择器写错，实际 `inMistakes = !resolved`，传 true 是移出。
- **自查**：打开实现看 flag 的真值方向，确认它是「开」还是「目标的否定」，再写调用。
- **等级**：强约束

## ③ UI 与渲染（4 条）

### U1 条件渲染的控件必须走重绘

- **规则**：按页签/展开态条件渲染的控件，状态变更必须重绘。
- **触发**：给已有页签新增按钮或区块。
- **来源**：M-018 / M-002
- **违规症状**：冒烟里一直 `btn=false`，手工点页签切过去按钮也不出现——因为原来只改 `hidden` 不重绘，按钮压根没被创建。
- **自查**：确认切换动作写进了 UI 状态对象并调用 `render()`；只改 `hidden` 只允许用在「两边内容都已存在」的场景。
- **等级**：红线

### U2 重绘不得覆盖未持久化输入

- **规则**：任何重绘路径不得覆盖草稿、异步结果、弹层状态。
- **触发**：加表单、加异步结果展示、加重绘入口。
- **来源**：M-002（M-001 / F-04 / F-05 三次同根因）
- **违规症状**：设置页「测试连接」结果一闪就没；edit/add 表单填一半被清空；tab 按钮 active 变了但内容区不动。
- **自查**：新状态先登记到 UI 状态对象再渲染；改完手工填一个草稿、触发一次重绘，看内容是否还在。
- **等级**：红线

### U3 静默降级必须透传到界面

- **规则**：兜底到另一套实现时，必须把降级事实和原因显示出来。
- **触发**：多引擎、多模型、多存储之间的失败回退。
- **来源**：M-020
- **违规症状**：用户说「语音播报的声音不是我们说好的那个声音」，界面一个字都没提示；查缓存发现 mp3 最新一条停在四天前，这几天在线通道一次都没成功。
- **自查**：搜 `catch` 里的 fallback 分支，确认返回 `fallback:{from,reason}` 且被 UI 消费；「兜底成功」不等于「没出事」。
- **等级**：红线

### U4 UI 改动必须过交互冒烟并同步断言

- **规则**：UI 改动必须跑交互冒烟；改控件名必须同步改断言。
- **触发**：改 HTML 结构、CSS 可见性、render 逻辑、事件绑定、控件名与选择器。
- **来源**：M-001 / M-008
- **违规症状**：`npm test` 全绿，但点顶部 tab 永远只显示题库页；或者控件改名后冒烟一直 `engine=false`，没人发现。
- **自查**：改完 grep 旧选择器是否还留在 `ui-smoke-main.js`；跑一次输出 `UI SMOKE OK` 才算过。
- **等级**：红线

## ④ AI 与外部服务（4 条）

### AI1 与 LLM 的结构化契约设三层防御

- **规则**：结构化契约按「可能空、可能不守格式」设计，三层缺一不可。
- **触发**：解析模型返回、开 JSON Mode、换模型。
- **来源**：M-021
- **违规症状**：同一请求连发 12 次，合法 7/12、纯空白 4/12、空串 1/12；`finish_reason=stop` 但 `content=""`，token 全花在 `reasoning_content` 上。用户看到「面试官暂未回应：AI 返回内容为空」。
- **自查**：对照「自动重试 → 结构化输出 → 解析兜底」三层逐项打勾；客户端零重试 + 严格解析就是缺两层。
- **等级**：红线

### AI2 失败回合必须整轮回滚

- **规则**：请求失败要撤回已落的库与前端草稿，不留半条记录。
- **触发**：先落库再请求的交互，以及「可以重发」类文案。
- **来源**：M-021（附带发现）
- **违规症状**：同一条候选作答在库里被插了 3 行；失败提示让用户重发，用户一点就多一条，对话史和报告被污染。
- **自查**：确认失败分支有撤回动作（撤消息、恢复草稿、不落库）；复现一次失败后查库行数有没有涨。
- **等级**：红线

### AI3 外部机制引用必须查源

- **规则**：引用外部产品机制必须查公开说明，禁止凭印象迁移。
- **触发**：类比他家产品、估算复习量、复述第三方算法。
- **来源**：第 10 轮（默默背单词）
- **违规症状**：被问「是否是纯艾宾浩斯」时贴标签，或者拿「大概是这么算的」当依据，一追问就露。
- **自查**：给结论时附公开说明链接或原文摘录；拿不到就标「未核实」，并改用模拟计算代替估数。
- **等级**：强约束

### AI4 断言「做不到」必须附穷举清单

- **规则**：说「做不到」必须列查过什么、没查什么，并给下一步动作。
- **触发**：判断某能力不存在、某入口走不通、某路径被堵死。
- **来源**：结论骨架 B7（第 20–21 轮）
- **违规症状**：断言「没有可编程入口，这条路走不通」，用户一句「你的意思是还是要耗费 key？」就推翻——原来只查了 PATH、文档索引、安装根目录，漏了 `app.asar.unpacked`。
- **自查**：写下「查了 A/B/C，没查 D」；清单缺项时只能说「暂未找到」，不能说「做不到」。
- **等级**：红线

## ⑤ 协作与流程（5 条）

### CO1 用户前提有误先纠偏再执行

- **规则**：用户前提有误时先纠偏再动手，不顺着错前提交付。
- **触发**：用户对已实现行为的理解与代码不一致时。
- **来源**：结论骨架 A5（第 27 轮、第 10 轮）
- **违规症状**：按错的理解改完，用户发现「和现在实现对不上，免得你按错的方式去用」。
- **自查**：先复述「你以为的是 X，实际是 Y」，等确认再执行；不复述就直接开工视为违规。
- **等级**：红线

### CO2 裁决变更必须广播全窗口并声明前序作废

- **规则**：裁决反转要广播所有相关窗口，并写明「以本条为准、前序作废」。
- **触发**：多窗口并行时的裁决被复检推翻。
- **来源**：结论骨架 B8 / M-005
- **违规症状**：出处链接先裁「答案文档」后反转为「题干文档」，反转只通知了内容窗口和用户，漏了提出复检的质检窗口；两个窗口按新旧两套口径各写一份文档，靠主控再对账一轮才收口。
- **自查**：变更后列出全部相关窗口（含提出方与被转达方），逐个确认收到；合并前核对各窗口文档口径与主仓数据一致。
- **等级**：红线

### CO3 格式未定稿前不批量生产

- **规则**：样式类产出必须先显式定稿，再批量生产。
- **触发**：批量写题、批量生成文档、批量改模板。
- **来源**：结论骨架 A2（第 6 轮）
- **违规症状**：返工全部发生在定稿之前——第 2、3 轮反复改格式；定稿之后 151 题零格式返工。
- **自查**：先出 2–3 个样张，拿到一句明确的「以后也按照这个格式来」再开工。
- **等级**：强约束

### CO4 同一修法一次扫全仓

- **规则**：修一类问题时扫全仓同类点，不只改报错的那一处。
- **触发**：修基建、修验收脚本、修选择器。
- **来源**：M-009 补充
- **违规症状**：`acceptance-live` 与 `acceptance-mdlite` 都改了降级截图，`acceptance-drafts.js` 漏改；窗口再被遮挡时又超时，20 条打成 19/20。
- **自查**：修完 grep 同类调用点，逐个数清有几个文件、改了几个。
- **等级**：强约束

### CO5 门禁为 merge 留通道，git 成败不接管道

- **规则**：门禁必须放行 merge/revert；验证 git 成败不许接管道。
- **触发**：合并分支、脚本化提交。
- **来源**：M-003
- **违规症状**：`merge: ...` 被 commit-msg 拒收，两次合并卡在 `still merging`；`git commit ... | tail` 让管道吞掉退出码，一度误判提交成功。
- **自查**：合并前确认 hook 有 `MERGE_HEAD` 分支；git 命令单独执行，成败查 `git log`/`git status` 坐实。
- **等级**：红线

## ⑥ 环境与工具（4 条）

### EN1 测试环境必须与运行环境并存

- **规则**：验收环境与运行环境必须能同时存在，不能就第一周修。
- **触发**：需要独占实例、单实例锁的验收。
- **来源**：结论骨架 B4（5 次阻塞：第 16、18、25、29、30 轮）
- **违规症状**：验收起不来，要用户手动关应用、回一句「关了」再补跑；第 19、29 两轮用户只回了两个字，全部价值就是替 AI 解锁环境。
- **自查**：验收前确认能并行拉起第二个实例；不能就先改端口或数据目录，而不是让用户关应用。
- **等级**：红线

### EN2 交给用户执行的脚本，按「谁解释它」分档

- **规则**：先确认脚本由谁解释——**cmd.exe 解释的（`.cmd` / `.bat`）零非 ASCII，注释也不行**；**bash / sh 解释的（`.sh`）可保留中文，但文件须 UTF-8、且确认执行环境有 bash**。共同要求：可一键撤销、优先给一次性命令而不是文件。
- **触发**：任何要用户在自己机器上执行的脚本或命令。
- **来源**：结论骨架 B6（第 24 轮，`.cmd` 事故）+ 2026-11-07 实测修订。修订原因：本项目 `install.sh` 含 35 行中文，在 Git Bash 下完全正常，但按旧规则属"违规"——说明原规则粒度过粗，把"解释器不匹配"错写成了"不能有中文"。
- **违规症状**：cmd.exe 按代码页（GBK）解析 UTF-8，中文注释被拆成乱码并当命令执行，用户「输入任何东西都会直接闪退」——本次唯一一次让用户机器进入不可用状态。
- **自查**：看扩展名 → 判断由谁解释 → 只在该解释器的编码风险下检查。`.sh` 额外确认两点：文件是 UTF-8、执行者是 bash 而非 cmd。
- **等级**：红线

### EN3 含反引号的内容禁用 node -e 写入

- **规则**：内容可能含反引号或 `$(` 时，写临时脚本文件执行，禁用 `node -e`。
- **触发**：批量改文档、改含模板字符串的代码。
- **来源**：M-016（第 3 次升级为硬规则）
- **违规症状**：bash 把反引号当命令替换吃掉，写进文件的代码变成 `await evaluate( , 10000 );`，`node --check` 报 `Unexpected token ','`。
- **自查**：命令里出现 `node -e` 且内容可能含反引号，立即改写临时文件再执行。
- **等级**：红线

### EN4 高频路径禁止 getState()

- **规则**：每请求、每帧、每句的路径禁止 `getState()`，只读需要的表。
- **触发**：TTS 逐句合成、渲染循环、请求前置检查。
- **来源**：M-006
- **违规症状**：缓存命中的合成请求，主进程只花 2ms，渲染层却等 2051ms；151 题整表读一次 2042ms，每句白付 2 秒。
- **自查**：搜高频路径里的 `getState()`，换成专用 getter；引入「每请求读一次」的数据源前先量单位成本并写进注释。
- **等级**：强约束

## 规则的退役条件

规则只增不删会退化成没人读的长文。但先搞清楚"重复"到底有多严重：本次 3 个 rules 文件 143 行里，真正与 CLAUDE.md 重复的只有 **4 句规则声明，占 5%**（2026-11-06 实测，删完只减 3 行）——重复不是主要问题，**"冲突以谁为准"没规定才是**。满足以下任一条即可删除，删除时在提交信息里写明依据：

1. **触发场景已消失**：规则指向的文件、命令、流程在仓库里已不存在（例如某个验收脚本被删除、某条 IPC 通道下线），规则已无处命中。
2. **已被更强机制固化**：该问题现在能被门禁或测试自动拦住，人不需要再记住它——规则的存在价值从「提醒」变成「噪声」，应把判据留在测试里而不是清单里。
3. **自上次回顾以来零命中，且举不出一次它拦下问题的实例**：「没出事」本身不是保留理由；说不清它上次生效是什么时候，就说明它已经不起作用。

反例（不可作为退役理由）：规则写得太严、执行起来麻烦、这次任务特殊。这三类属于「偏离需说明理由」，走强约束的例外流程，不走退役。
